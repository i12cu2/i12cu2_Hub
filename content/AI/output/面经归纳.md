## 一、算法与数据结构

1. **数组、链表、二叉树、堆栈、排序、B/B+树、DP**
   - 数组：随机访问 O(1)，插入删除 O(n)，连续内存。
   - 链表：插入删除 O(1)（已知位置），查找 O(n)，非连续内存。
   - 二叉树：遍历前中后序、层序；BST 中序有序；平衡树避免退化。
   - 堆栈：栈后进先出，队列先进先出；单调栈可解下一个更大元素等。
   - 排序：快排平均 O(n log n)、最坏 O(n²)；归并稳定 O(n log n)；堆排 O(n log n) 不稳定。
   - B 树/B+树：B 树各节点存数据；B+树内部节点只存索引，数据全在叶子，叶子链表，范围查询和磁盘 IO 更优。
   - DP：定义状态、转移方程、初始化、边界、遍历顺序，必要时滚动数组/单调队列优化。

2. **检查二叉树是否平衡**
   - 递归求左右子树高度，若任一子树不平衡返回 -1。
   - 若左右高度差 > 1，返回 -1；否则返回 `max(left,right)+1`。
   - 时间复杂度 O(n)，每个节点访问一次。

3. **两个字符串大数除法**
   - 模拟竖式除法：从高位逐位取当前余数，补下一位，试商 0~9，减去除数，记录商和余数。
   - 时间复杂度 O(n×10)，可二分试商优化。
   - 注意前导零、除数为 0、负数符号。

4. **实现堆栈，使 push、pop、max 都是 O(1)**
   - 主栈存数据，辅助栈存“当前最大值”。
   - push：主栈入栈；辅助栈入 `max(x, 辅助栈顶)`。
   - pop：两栈同时弹出。
   - max：辅助栈顶。
   - 空间 O(n)。

5. **若干个数组的所有可能组合**
   - 本质是笛卡尔积或子集/组合问题。
   - 若每个数组取一个：回溯/DFS，每层选一个元素，递归下一数组。
   - 若求所有子集：回溯，每个元素选或不选，O(2^n)。
   - 注意空集、顺序、去重。

6. **圆和 OBB 相交检测**
   - 把圆心变换到 OBB 局部坐标系。
   - 将圆心坐标 clamp 到 OBB 的半长宽范围，得到 OBB 上最近点。
   - 比较圆心到最近点距离平方与半径平方。
   - 若圆心已在 OBB 内，直接相交。
   - 2D 中常用 `Vector2.Max/Min` 做 clamp，代码很短。

7. **链表穿针引线**
   - 常见为链表重排、反转、合并、找中点。
   - 快慢指针找中点，反转后半段，再交替合并。
   - 时间 O(n)，空间 O(1)。

8. **树最大深度**
   - `maxDepth(root)=max(maxDepth(left),maxDepth(right))+1`。
   - 空节点返回 0。时间 O(n)。

9. **多个数排列成一个数，使其最小**
   - 转字符串，排序规则：`a+b < b+a` 则 a 在前。
   - 拼接后处理前导零，若全零返回 "0"。
   - 时间 O(n log n)。

10. **两个 10G 文件，200M 内存，排序**
    - 外部排序：分块读入 200M 内存，排序后写临时文件。
    - 多路归并：每个临时文件读一块，用小顶堆选最小，输出到最终文件。
    - 若有重复数据，可排序后去重，或哈希分桶后各桶排序。
    - 关键是减少磁盘 IO、归并路数、缓冲区大小。

11. **红黑树最坏搜索复杂度**
    - O(log n)。
    - 红黑树近似平衡，最长路径不超过最短路径两倍，树高 O(log n)。
    - 插入删除通过旋转和变色维持性质。

## 二、计算机网络

1. **TCP 与 UDP**
   - TCP：面向连接、可靠、有序、字节流、流量控制、拥塞控制、头部 20 字节起。
   - UDP：无连接、不可靠、无序、数据报、头部 8 字节、开销小、延迟低。
   - 游戏实时同步常用 UDP，应用层实现可靠/有序/加密。

2. **TCP 拥塞控制**
   - 慢启动：cwnd 指数增长。
   - 拥塞避免：cwnd 线性增长。
   - 快重传：收到三个重复 ACK 立即重传。
   - 快恢复：ssthresh 减半，cwnd 从新 ssthresh 开始。
   - 核心是 cwnd、ssthresh、RTT、丢包判断。

3. **DNS**
   - 域名解析，通常 UDP 53；区域传输用 TCP。
   - 递归查询、迭代查询；缓存 TTL。
   - 根、顶级域、权威域名服务器。

4. **ping**
   - 使用 ICMP Echo Request / Echo Reply。
   - 测试连通性、RTT、丢包。

5. **ARP**
   - 局域网内 IP 地址解析为 MAC 地址。
   - 广播 ARP Request，单播 ARP Reply，有缓存。

6. **HTTP**
   - 应用层协议，请求-响应，无状态。
   - HTTPS = HTTP + TLS，加密、认证、完整性。

7. **select、poll、epoll**
   - 都是 I/O 多路复用，本质是同步 I/O：就绪后还要自己读写。
   - select：fd_set，有 1024 限制，O(n) 轮询，每次拷贝。
   - poll：pollfd 数组，无 1024 限制，仍 O(n) 轮询。
   - epoll：红黑树管理 fd，就绪链表回调，O(1) 取就绪，mmap 减少拷贝，支持 LT/ET。
   - 异步 I/O 由内核完成数据拷贝到用户空间，用户无需自己读写。

8. **安全 UDP**
   - 在 UDP 上实现可靠、有序、拥塞控制、加密。
   - 代表：QUIC、KCP。
   - QUIC：多路复用、0-RTT、TLS 集成、避免队头阻塞。

9. **三次握手状态变换**
   - 客户端：CLOSED → SYN_SENT → ESTABLISHED。
   - 服务端：CLOSED → LISTEN → SYN_RCVD → ESTABLISHED。
   - 目的：同步序号、确认双方收发能力、防止历史连接。

10. **32 位系统初始内存空间**
    - 32 位地址总线可寻址 2^32 = 4GB 虚拟地址空间。
    - Linux 通常用户态 3GB、内核 1GB；Windows 默认可能 2GB/2GB。
    - 不是每个进程一开始就占满 4G 物理内存。

## 三、操作系统

1. **进程与线程**
   - 进程：资源分配基本单位，独立地址空间。
   - 线程：CPU 调度基本单位，共享进程资源，切换开销小。
   - 线程通信：共享内存、互斥量、信号量、条件变量、管道、消息队列。

2. **互斥量与信号量**
   - 互斥量：0/1，有所有权，用于临界区互斥。
   - 信号量：计数，可用于同步和互斥，P/V 操作。

3. **线程挂起与执行**
   - 线程状态：新建、就绪、运行、阻塞、终止；挂起是换出到外存。
   - 调度器根据优先级、时间片、等待资源决定。
   - 线程不是任何时间都能阻塞/挂起：内核关键区、持自旋锁、原子上下文不能随意阻塞；用户态需在安全点。

4. **死锁**
   - 四个必要条件：互斥、占有并等待、不可抢占、循环等待。
   - 处理：预防、避免、检测、解除。
   - 预防：资源有序分配、一次性申请、可抢占。

5. **处理器调度**
   - FCFS、SJF、RR、优先级、多级反馈队列。
   - 指标：周转时间、响应时间、吞吐量、CPU 利用率。

6. **IO、存储器、设备管理、通道**
   - IO：程序控制、中断、DMA、通道。
   - 存储器：分页、分段、虚拟内存、页面置换。
   - 设备管理：缓冲、缓存、假脱机、设备驱动。
   - 通道：专门 IO 处理器，减少 CPU 干预。

7. **多线程编程注意事项**
   - 明确为什么用多线程：IO 瓶颈用线程池，多资源管理用多线程。
   - 控制调度和阻塞：事件、消息。
   - 公共资源必须加锁，避免死锁。
   - 合理 Sleep，减少 CPU 抢占；非阻塞循环每轮适当 Sleep。
   - 线程终止尽量自然完成，不要随意抛异常。
   - 线程优先级要有整体规划。

## 四、C++ 与编译链接

1. **动态分配内存**
   - `new`：在堆上分配并调用构造函数；`delete` 调用析构并释放。
   - `new[]` 配 `delete[]`。
   - `malloc/free` 只分配释放内存，不调用构造/析构。
   - 内存分区：栈、堆、全局/静态区、常量区、代码区。

2. **单例**
   - 懒汉式：第一次用时创建。C++11 静态局部变量线程安全。
   - 饿汉式：类加载时创建，天然线程安全，但可能提前初始化。
   - 双检锁：`atomic` + mutex，注意内存序。

3. **哪些函数不能是虚函数**
   - 构造函数不能虚：对象未建立，虚表指针未初始化。
   - 静态成员函数不能虚：不属于对象。
   - 友元、非成员函数不能虚。
   - 析构函数可以且基类应虚。

4. **C++ 特性：指针、智能指针、引用、右值引用**
   - 指针：直接操作地址，可为空，可重新赋值。
   - 智能指针：`unique_ptr` 独占，`shared_ptr` 共享计数，`weak_ptr` 解决循环引用。
   - 左值引用绑定左值；右值引用绑定右值，支持移动语义、完美转发。
   - 移动语义减少拷贝，提高性能。

5. **内存布局与内存对齐**
   - 对象内存：成员变量、虚表指针、继承布局。
   - 对齐：成员按对齐要求排列，结构体大小为最大对齐的整数倍，可能有 padding。
   - `alignas` 可指定对齐。

6. **函数调用过程**
   - 参数传递：寄存器/栈。
   - `call` 压入返回地址。
   - 被调函数保存栈帧、分配局部变量。
   - 执行后恢复栈帧、返回。

7. **多线程锁**
   - 互斥锁、读写锁、自旋锁、条件变量、原子操作。
   - 注意死锁、锁粒度、优先级反转。

8. **编译过程**
   - 预处理 → 编译 → 汇编 → 链接。
   - 静态链接：库代码复制进可执行文件。
   - 动态链接：运行时加载共享库，节省空间，便于更新。

## 五、游戏开发、图形学与引擎

1. **NavMesh 动态寻路**
   - 烘焙每个房间 NavMesh，链接房间预制体。
   - 动态障碍可用 `NavMeshObstacle` + Carving，或运行时重新烘焙/分层。
   - 跨房间用 Off-Mesh Link 或连接点。

2. **随机地图与对象池**
   - 随机地图：房间生成、位置检测、连接、避免重叠。
   - 防止房间重叠：遍历 O(n²)，优化用网格 bitset、空间哈希、四叉树。
   - 对象池：预实例化，复用对象，减少 Instantiate/Destroy 和 GC。

3. **子弹碰撞**
   - 玩家和敌人不同 Tag/Layer，碰撞时检测目标 Tag，防止友伤。
   - 粒子效果，子弹未命中可用 `OnBecameInvisible` 销毁。
   - 更稳：生命周期、射线检测、对象池回收。

4. **直线和球相交**
   - 球隐式：`(P-C)·(P-C)=r²`。
   - 直线：`P=O+tD`。
   - 代入得二次方程：
     `t²(D·D)+2tD·(O-C)+(O-C)·(O-C)-r²=0`。
   - 判别式 ≥0 有交点，求 t。

5. **圆和 OBB 相交**
   - 圆心转到 OBB 局部坐标，clamp 到半长宽，求最近点，比较距离平方和半径平方。
   - 3D 中 OBB 用 SAT 分离轴。

6. **DX 雾效**
   - 在 Shader 中按深度计算雾因子。
   - 线性雾、指数雾、指数平方雾，混合 `fogColor`。
   - 顶点/像素着色器均可，像素更精细。

7. **公告板**
   - Billboard，四边形始终面向相机。
   - 顶点着色器构造面向相机的坐标系，或 CPU 每帧旋转。

8. **VR 项目**
   - Pico VR SDK，Hierarchy 中相机。
   - 场景放球壳体，相机在球内，VR 视频纹理渲染到球内表面。

9. **DrawCall**
   - CPU 向 GPU 提交绘制命令。
   - 优化：合批、图集、GPU Instancing、减少状态切换、LOD。

10. **天空盒**
    - CubeMap 六个面，按视线方向采样。
    - 内套球/立方体，纹理映射到内表面。
    - 动态天空盒：滚动噪声、体积云、体积雾；简单滚动纹理会有接缝和视差问题。

11. **纹理压缩**
    - Mipmap 是纹理金字塔，用于 LOD，不是压缩本身。
    - 压缩格式：ASTC、ETC2、DXT/BC。
    - 减少带宽和内存。

12. **碰撞检测优化**
    - 八叉树、四叉树、BVH、空间哈希。
    - 物体跨多个叶子：BVH 物体划分，或松八叉树，或记录去重。

13. **渲染管线**
    - 应用阶段 → 几何阶段 → 光栅化 → 像素阶段 → 输出。
    - 顶点变换、裁剪、屏幕映射、光栅化、片元着色、混合。

14. **延迟渲染**
    - 先写 G-buffer：位置、法线、Albedo、粗糙度等。
    - 后置光照阶段统一计算，适合多光源。
    - 缺点：带宽高、透明物体麻烦。

15. **齐次坐标与透视除法**
    - n 维用 n+1 维表示，统一平移/旋转/缩放。
    - 透视除法：`x/w, y/w, z/w`，实现近大远小。

16. **光栅化与光线追踪**
    - 光栅化：三角形投影到屏幕，局部光照，快。
    - 光追：从相机发射光线，模拟反射折射阴影，全局效果，慢但真实。

17. **不用 UI 组件显示图片**
    - 创建 Quad/Plane，材质贴图。
    - Shader 采样纹理，顶点 UV 插值，片元输出颜色。
    - 上色过程就是 Shader。

18. **IK、BlendTree、行为树**
    - IK：反向动力学，脚踩石头用射线检测地面，调整脚部骨骼。
    - BlendTree：按参数混合多个动画，1D/2D。
    - 行为树 vs 状态机：状态机状态转移明确；行为树层次化、可复用，适合复杂 AI。

19. **冯·诺依曼与哈佛结构**
    - 冯·诺依曼：指令和数据统一存储、同一总线，又称普林斯顿结构。
    - 哈佛：指令和数据分开存储、分开总线。
    - 计算机层次：硬件 → 微程序 → 机器语言 → 操作系统 → 汇编 → 高级语言 → 应用。
    - 性能指标：主频、CPI、MIPS、吞吐量、响应时间、加速比。

## 六、联机与系统设计

1. **联机考虑什么**
   - 同步：状态同步、帧同步。
   - 服务器计算 vs 客户端计算。
   - 服务器计算：安全、反作弊好，但压力大、延迟高。
   - 客户端计算：响应快、服务器压力小，但易作弊、状态不一致。
   - 常用折中：客户端预测 + 服务器校验 + 回滚。

2. **网络同步协议**
   - 实时游戏用 UDP，应用层优化：可靠 UDP、有序、拥塞控制。
   - 代表：QUIC、KCP。
   - 登录、聊天、排行榜可用 TCP。

3. **FPS 方向**
   - 先从 UI、战斗逻辑、武器、角色控制做起，熟悉开发流程。
   - 再深入同步、反作弊、动画、渲染优化。

## 七、附加高频总结

- **select/poll/epoll**：I/O 多路复用，同步 I/O；epoll 更适合高并发。
- **多线程**：明确目的、控制调度、保护共享资源、避免死锁、合理 Sleep、自然终止、规划优先级。
- **单例**：懒汉用时创建，饿汉加载创建；C++11 静态局部变量线程安全。
- **红黑树**：最坏 O(log n)。
- **TCP/UDP**：可靠有序 vs 低延迟；游戏实时多用 UDP。
- **三次握手**：SYN → SYN+ACK → ACK，状态 CLOSED/LISTEN/SYN_SENT/SYN_RCVD/ESTABLISHED。
